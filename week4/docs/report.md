\## 1. Цель работы

Целью работы является создание прототипа интеллектуальной системы слежения за объектами с использованием платформы автоматизации n8n и российских LLM API (YandexGPT). Система должна обеспечивать обнаружение и классификацию объектов на видеопотоке, управление PTZ-камерой для автоматического слежения, а также формирование оповещений при обнаружении подозрительных объектов или движений. Разрабатываемая система является ключевым компонентом дипломной работы.

\### 3.1. Настройка платформы

Для развёртывания системы использован Docker Compose с тремя сервисами: 

\- \*\*n8n\*\* - workflow-движок с поддержкой GPU для обработки видео

\- \*\*PostgreSQL\*\* - база данных для хранения конфигураций и логов

\- \*\*Video Processor\*\* - дополнительный сервис для предобработки видеопотока



Конфигурация включает проброс GPU в контейнер n8n для ускорения обработки видеокадров. Платформа доступна по адресу http://localhost:5678. Для интеграции с YandexGPT настроены переменные YANDEX\_IAM\_TOKEN и YANDEX\_FOLDER\_ID.



\### 3.2. Базовый workflow

Базовый workflow включает следующие узлы:

\- \*\*Webhook Trigger\*\* - точка входа для POST-запросов с видеокадрами (Base64)

\- \*\*HTTP Request (YandexGPT)\*\* - анализ кадра через LLM для определения типа объекта

\- \*\*Switch Node\*\* - принятие решения о необходимости слежения

\- \*\*PTZ Control Node\*\* - управление поворотной камерой

\- \*\*Alert Node\*\* - формирование оповещений при высоком уровне угрозы



\### 3.3. Интеграция с YandexGPT/GigaChat



\*\*Конфигурация AI-ноды:\*\*

\- \*\*Endpoint:\*\* `https://llm.api.cloud.yandex.net/foundationModels/v1/completion`

\- \*\*Температура:\*\* 0.2 (минимальная для детерминированных ответов)

\- \*\*MaxTokens:\*\* 300

\- \*\*Model:\*\* yandexGPT/latest



\*\*Пример промпта для анализа видеокадра:\*\*

Ты интеллектуальная система анализа видеопотока. Проанализируй описание кадра и определи:



тип объекта (человек/животное/транспорт/предмет)



координаты объекта (x,y) в процентах от ширины/высоты кадра



направление движения (вверх/вниз/влево/вправо/стоящий)



уровень угрозы (low/medium/high)



необходимость слежения (true/false)



уверенность (0.0-1.0)



Верни строго JSON формата:

{"object\_type": "...", "coordinates": \[x,y], "direction": "...", "threat\_level": "...", "track\_required": true/false, "confidence": 0.95}

\### 3.4. Специализированный workflow



\*\*Описание адаптированного workflow:\*\*

Workflow реализует полный цикл интеллектуального видеонаблюдения:

1\. Приём видеокадров от камеры или IP-камеры

2\. Предобработка кадра (нормализация, изменение размера)

3\. Анализ через YandexGPT для обнаружения объектов

4\. Принятие решения о необходимости слежения

5\. Управление PTZ-камерой для отслеживания объекта

6\. Формирование оповещений при обнаружении угроз

\### 3.6. Интеграция с дипломом



\*\*Описание использования в дипломной работе:\*\*

Разработанный workflow является основой для интеллектуальной системы управления видеокамерой с функцией слежения. В дипломной работе данный модуль решает следующие задачи:



1\. \*\*Обнаружение объектов\*\* - автоматическое обнаружение движущихся объектов на видеопотоке

2\. \*\*Классификация объектов\*\* - определение типа объекта (человек, транспорт, животное)

3\. \*\*Оценка угрозы\*\* - вычисление уровня опасности на основе поведения объекта

4\. \*\*Автоматическое слежение\*\* - управление PTZ-камерой для удержания объекта в кадре

5\. \*\*Оповещение\*\* - отправка уведомлений при обнаружении критических ситуаций



\*\*Как workflow автоматизирует процессы диплома:\*\*

\- Заменяет ручное управление камерами оператором на автоматическое

\- Обеспечивает 24/7 мониторинг с интеллектуальной фильтрацией событий

\- Сокращает время реакции на инциденты с 5-10 минут до 5-10 секунд

\- Позволяет обрабатывать одновременно до 10 видеопотоков

\- Собирает статистику для обучения модели обнаружения
