## 3. Ход работы
### 3.1. Архитектура RAG системы
Разработанная RAG-система состоит из следующих ключевых компонентов:
┌─────────────┐ ┌─────────────┐ ┌─────────────┐ ┌─────────────┐
│ Загрузка │────▶│ Разбиение │────▶│ Векторное │────▶│ Поиск │
│ документов │ │ на чанки │ │ хранилище │ │ (Retrieve)│
└─────────────┘ └─────────────┘ └─────────────┘ └─────────────┘
│ │ │ │
▼ ▼ ▼ ▼
PDF, TXT, MD Recursive Split ChromaDB + Semantic
DOCX файлы Size: 512 Embeddings Search
Overlap: 50
│
▼
┌─────────────┐ ┌─────────────┐ ┌─────────────┐ ┌─────────────┐
│ Пользова- │────▶│ Формиро- │────▶│ LLM │────▶│ Генерация │
│ тельский │ │ вание │ │ (YandexGPT)│ │ ответа │
│ запрос │ │ промпта │ │ │ │ (Generate)│
└─────────────┘ └─────────────┘ └─────────────┘ └─────────────┘
**Принцип работы:**
1. Загрузка документов из директории `data/documents/`
2. Разбиение текста на семантически связанные чанки
3. Векторизация чанков с помощью модели paraphrase-multilingual-MiniLM-L12-v2
4. Сохранение векторов в ChromaDB
5. При запросе — поиск релевантных чанков по косинусному сходству
6. Формирование промпта с контекстом из найденных чанков
7. Генерация ответа через YandexGPT

### 3.2. Настроенные компоненты
| Компонент | Реализация | Параметры |
|-----------|-----------|-----------|
| Document Loader | LangChain DocumentLoaders | Форматы: PDF, TXT, MD, DOCX |
| Chunking | RecursiveCharacterTextSplitter | Size: 512 символов, Overlap: 50 |
| Embeddings | HuggingFaceEmbeddings | Модель: paraphrase-multilingual-MiniLM-L12-v2, Dimension: 384 |
| Vector Store | ChromaDB | Collection: construction_documents, Persist: ./data/chroma_db |
| LLM | YandexGPT | Temperature: 0.3, Max tokens: 500 |
